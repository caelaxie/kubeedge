# AGENTS.md

Assistant guidance for changes under `edge/`.

## Scope

- Applies to all files in `edge/**`.
- Follow root `/AGENTS.md` first; this file adds edge-specific rules.

## Edge component map

- Entrypoints are under `edge/cmd/` (`edgecore`, `edgemark`).
- Main implementation code is under `edge/pkg/`.
- Edge-side integration tests are under `edge/test/integration/`.
- Mocks are under `edge/mocks/` (many files are generated).

## How to validate edge changes

Run from repository root:

- Fast path: `make test WHAT=edge`
- Broader checks: `make verify` and `make lint`

When change impacts edge runtime integration (message flow, module wiring, runtime interactions):

- Run edge integration script: `edge/test/integration/scripts/execute.sh`
- Or run full integration target: `make integrationtest`

When change impacts cloud-edge e2e behavior:

- Run `make e2e` (heavy; requires kind/container runtime tooling).

## Runtime and test caveats

- Some integration/e2e scripts use `sudo`, kill running processes, and clean temp paths; avoid running them casually.
- Edge tests and docs may rely on local services (e.g., MQTT, sqlite-based state) and runtime setup.

## Generated code and mocks

- Do not hand-edit files marked generated (e.g., `edge/mocks/**` generated by MockGen).
- Regenerate generated artifacts via the project’s existing scripts/tools where relevant.
